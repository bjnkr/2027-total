# 검증 결과 — 2026-10-26

검증 범위는 현재 서비스 코드(`frontend`, `api`, 테이블 설치 파일)입니다. 원본 참고 폴더는 실행 대상에서 제외했습니다.

## 발견 및 수정

- API의 실제 계산과 상세내역 계산에 중복 구현이 있었습니다. 상세 계산 결과에서 각 제도의 소득인정액을 산출하도록 통합했습니다. 중복 정리 전후 160개 사례의 응답을 비교해 기존 값이 유지됨을 확인했습니다.
- 주거급여 재계산 화면이 8~10인 가구를 7인으로 제한하고 있었습니다. 클라이언트의 중복 기준임대료 표를 제거하고, API가 가구원 수에 맞는 지역별 기준임대료를 반환하도록 수정했습니다.
- 저장된 정보의 문자열 `"false"`, 부분적인 단위 설정, 짧은 월별 배열 등을 복원할 때 잘못 표시되거나 오류가 날 수 있었습니다. 기본값 병합과 자료형 정규화를 추가했습니다.
- 잘못된 API 입력이 PHP 경고를 발생시켜 JSON 응답을 깨뜨릴 수 있었습니다. 입력 검증, 단위·선택값 검사와 명확한 HTTP 400 응답을 추가했습니다.
- React 정적 검사 오류 11개를 해결했습니다. 컴포넌트를 렌더링 중에 다시 정의하던 문제, Effect에서 불필요하게 상태를 초기화하던 부분, 순환 import 및 타입·미사용 변수 문제를 정리했습니다.
- 테이블 설치 파일과 별도 SQL 파일의 정의가 달랐습니다. 설치 파일이 `api/create_table.sql`을 사용하도록 통합했습니다. PHP 공통 파일 경로도 현재 작업 디렉터리에 영향을 받지 않도록 수정했습니다.
- 개발 의존성의 보안 경고 8건을 호환 버전 업데이트로 해결했습니다. `npm audit` 결과 0건입니다.

## 확인한 항목

- TypeScript 검사와 프로덕션 빌드
- ESLint 검사
- PHP 19개 파일 문법 검사(API·게시판 스킨·설치 파일)
- 기존 계산·상세 화면 23개 사례, 92개 제도별 결과
- 4개 지역 × 1~10인 × 전세/자가 × 특례 선택 여부: 160개 사례, 640개 제도별 결과
- 네 지역의 순재산·금융재산 특례 기준과 기준 + 1원: 16개 경계 사례
- 잘못된 요청 14개, 부분 입력, 콤마 금액, 문자열 boolean, 원/만원 동등성
- 저장된 입력정보의 복원과 비로그인 이력 조회
- Chromium 1280px / 360px: 입력 복원 → 단계 이동 → 계산 → 8인 주거급여 재계산 → 상세창 → 의료급여 전환 → 월별 표 → 자동 스크롤 → 닫기
- 위 브라우저 흐름에서 실행 오류와 상세창 가로 넘침 없음

## 재실행

루트 폴더에서 PHP 개발 서버를 실행한 뒤 프런트엔드 개발 서버를 실행합니다. PHP가 PATH에 없다면 설치된 `php.exe`의 전체 경로를 사용합니다.

```powershell
# 프로젝트 루트, 별도 터미널
php -S 127.0.0.1:8088 -t .

# frontend 폴더, 별도 터미널
npm ci
npm run dev -- --port 5173

# frontend 폴더, 검증 터미널
npm run build
npm run lint
npm run verify
npx playwright install chromium
npm run verify:browser
npm audit
```

- 운영 서버의 실제 그누보드 로그인·회원별 DB 저장/복원과 기존 DB 스키마 마이그레이션은 로컬 비로그인 환경에서 검증하지 않았습니다. 이번 점검에서는 실제 DB를 생성하거나 수정하지 않았습니다.
- 정책 기준액 자체의 최신 고시 적합성을 재판정한 작업은 아닙니다. 저장된 기존 계산 기준의 일관성과 동작을 검증했습니다.
- `InterestIncomeDetailsModal.tsx`, `PrivateTransferDetailsModal.tsx`와 `api/calcCommon.txt`, `api/getDetails.txt`는 현재 실행 코드에서 참조되지 않는 이전 구현/백업입니다. 사용 중인 계산 경로와 구분해 보존했습니다.
